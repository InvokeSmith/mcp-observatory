# Exactly what this scanner sends

Generated by `tests/support/capture-example-requests.ts` from a real probe against a local
fixture server, so it cannot drift from the code. If the prober starts sending something else,
this file changes.

An operator deciding whether to care about us should not have to read our source, or take our
word for it. This is the whole of it.

Identity on every request: `mcp-observatory/0.1.0-alpha.1 (+https://github.com/invokesmith/mcp-observatory)`
Opt out: https://github.com/invokesmith/mcp-observatory/blob/main/OPTOUT.md

## The complete sequence for one host

5 HTTP requests against an open server. There is no branch that makes more, and
most hosts see fewer: a server that declines via the well-known gets one request and nothing
else, and a server that answers with a credential challenge gets no second attempt.

### 1. `GET /.well-known/mcp-scan-optout`

```http
GET /.well-known/mcp-scan-optout HTTP/1.1
user-agent: mcp-observatory/0.1.0-alpha.1 (+https://github.com/invokesmith/mcp-observatory)
```

Response: `404`, 9 bytes.

### 2. `POST /mcp`

```http
POST /mcp HTTP/1.1
accept: application/json, text/event-stream
content-type: application/json
user-agent: mcp-observatory/0.1.0-alpha.1 (+https://github.com/invokesmith/mcp-observatory)
```

Response: `200`, 168 bytes.

### 3. `POST /mcp`

```http
POST /mcp HTTP/1.1
accept: application/json, text/event-stream
content-type: application/json
mcp-protocol-version: 2025-06-18
user-agent: mcp-observatory/0.1.0-alpha.1 (+https://github.com/invokesmith/mcp-observatory)
```

Response: `202`, 0 bytes.

### 4. `GET /mcp`

```http
GET /mcp HTTP/1.1
accept: text/event-stream
mcp-protocol-version: 2025-06-18
user-agent: mcp-observatory/0.1.0-alpha.1 (+https://github.com/invokesmith/mcp-observatory)
```

Response: `400`, 11 bytes.

This one the scanner does not originate: it is the MCP SDK opening the server-to-client stream that the Streamable HTTP transport uses. We disclose it rather than omit it, because it is a request you will see in your logs. It carries no JSON-RPC method, it is counted against the same per-host request budget as everything else, and it goes through the same gate — a request the SDK makes to any origin the ticket does not name is refused before it opens a socket.

### 5. `POST /mcp`

```http
POST /mcp HTTP/1.1
accept: application/json, text/event-stream
content-type: application/json
mcp-protocol-version: 2025-06-18
user-agent: mcp-observatory/0.1.0-alpha.1 (+https://github.com/invokesmith/mcp-observatory)
```

Response: `200`, 521 bytes.

## The JSON-RPC bodies

Two methods, and the notification the protocol requires between them:

```json
{
  "jsonrpc": "2.0",
  "id": 0,
  "method": "initialize",
  "params": {
    "protocolVersion": "2025-06-18",
    "capabilities": {},
    "clientInfo": {
      "name": "mcp-observatory",
      "version": "0.1.0-alpha.1"
    }
  }
}
```

```json
{
  "jsonrpc": "2.0",
  "method": "notifications/initialized"
}
```

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/list",
  "params": {}
}
```

There is no `tools/call`. The transport this scanner uses cannot represent one — see
`src/mcp/gated-transport.ts` and `tests/constraints/constraint-01-no-tool-invocation.test.ts`.

Before any of the above, the scanner requests `/.well-known/mcp-scan-optout`. If that says
to go away, none of the above happens. See `protocol/MCP-SCAN-OPTOUT.md`.
